AI와 함께 두 사업계획서를 하나의 한글 요약본으로 합치기 — 표까지 자동 생성

요약

토론용 사업계획서 두 건(시민기금 10쪽, 시민기업펀드 8쪽)을 AI에게 맡겨 각 3쪽씩, 총 6쪽짜리 통합 요약 한글(.hwpx) 문서로 만들었다. 한글 프로그램을 한 번도 열지 않고, 원본 문서를 서식 템플릿 삼아 새 문서를 통째로 조립했다. 처음 나온 9쪽짜리 문단 요약본에 “표로 정리해서 6쪽으로”라고 한 줄 피드백하자, 나열식 내용이 표 10개로 재구성된 개정본이 나왔다.

왜 이 기술인가

  • 활동 현장에서는 긴 계획서 여러 건을 회의용 요약본 하나로 만드는 일이 반복된다. 사람이 하면 반나절, 서식 맞추다 하루가 간다.
  • 흔한 우회로(워드로 변환→요약→다시 한글)는 서식이 깨지고, 결국 한글에서 다시 손본다. 원본 hwpx의 서식(글자모양·문단모양·표 스타일)을 그대로 물려받는 조립 방식이면 이 재작업이 사라진다.
  • 핵심 요령은 “AI에게 문서를 새로 그리게 하지 말고, 원본을 템플릿으로 재사용하게 하는 것”이다.

단계별 따라하기

.hwpx는 ZIP 안에 XML이 든 포맷이라 PowerShell만으로 다룰 수 있다(파이썬·한컴 자동화 불필요).

1) 두 원본에서 텍스트 추출

AI에게 두 파일 경로를 주고 “핵심 내용을 각 3쪽씩 요약해 하나의 한글 문서로”라고 요청한다. AI는 hwpx를 압축 해제해 본문 XML(Contents/section0.xml)의 텍스트를 전부 덤프해 읽는다.

2) 원본에서 서식 ID 채록

새 문서의 문단이 원본과 똑같이 보이려면, 원본 문단이 쓰는 서식 번호(paraPrIDRef/charPrIDRef)를 그대로 쓰면 된다. 제목·절 제목·본문·표의 머리행/본문 셀 각각 하나씩 견본 문단을 열어 번호를 채록한다.

3) 요약 내용을 ‘스펙 파일’로 작성

본문을 XML로 직접 쓰지 않고, 한 줄 한 요소짜리 단순 마크업으로 쓴다:

H1|제1부. 시민기금 사업계획 요약
H2|1. 추진 배경
P| ㅇ 자부담 15%가 확산의 병목 ...
TBL|14000,11200,11200,11222      ← 열 너비(합계가 표 전체폭과 일치해야 함)
R|구분|보수|기준|적극              ← 첫 줄은 머리행(음영 처리)
R|기금 필요 규모|4,500억|6,200억|8,000억
END

이 스펙을 작은 생성기 스크립트가 문단·표 XML로 변환한다. 표는 행 수·셀 좌표·너비 검증까지 자동이라, 손으로 표 XML을 짜다 문서를 깨뜨릴 일이 없다.

4) 원본 뼈대에 새 본문 이식

원본 section0.xml에서 첫 문단(용지 설정·머리말이 든 뼈대)만 남기고 나머지를 전부 지운 뒤, 생성된 문단·표를 붙인다. 레이아웃 캐시(linesegarray)는 지워서 한글이 열 때 재계산하게 한다. 마지막으로 원본 ZIP에 새 XML만 갈아끼우면(재패키징) 완성이다.

5) 검증 후 피드백 반복

새 파일을 다시 덤프해 “있어야 할 문자열이 있는지”를 기계적으로 확인한다. 쪽수는 한글이 열 때 확정되므로, 열어 보고 “9쪽이나 되는데, 표로 정리해서 6쪽으로”처럼 분량·형식 피드백을 한 줄로 주면 된다. 이번 작업에서는 이 피드백 한 번으로 문단 나열 → 표 10개 구성으로 전면 재편됐다.

교훈

  1. 서식은 만들지 말고 물려받아라. 원본의 서식 ID를 재사용하면 “AI가 만든 티”가 나지 않는 문서가 나온다.
  2. 표가 압축의 핵심이다. 같은 내용도 나열 문단은 9쪽, 표 중심이면 6쪽이었다. 개요·시나리오·유형 비교·재원 목록처럼 구조가 있는 내용은 처음부터 표로 요청하는 게 빠르다.
  3. 내용과 형식을 분리하라. 요약 내용은 단순 텍스트 스펙으로 쓰고 XML 변환은 스크립트에 맡기니, 검토·수정이 쉬워지고 실수가 줄었다.
  4. 쪽수는 근사치다. hwpx에는 ‘쪽’이 저장되지 않는다. 내용량으로 목표에 근접시키고 최종 확인은 사람이 한글에서 한다.
  5. 원본은 절대 덮어쓰지 않는다. 산출물은 항상 새 파일명으로.
