핸드오버 2026-09-27 — gws 구글 워크스페이스 CLI 제작과 OAuth 설정

세션 요약

이사장님의 “gws cli를 만들어” 지시로 구글 워크스페이스(드라이브·문서·시트·지메일·캘린더)를 터미널에서 다루는 명령줄 도구 gws 를 만들었다. 이어서 이 도구가 쓸 구글 클라우드 프로젝트와 OAuth 클라이언트를 콘솔에서 설정했고, 사교원이 쓰는 지메일 계정 23개를 테스트 사용자로 등록하는 데까지 마쳤다. 아직 계정 로그인(토큰 발급)은 한 건도 하지 않았으므로 다음 세션에서 그것부터 이어가면 된다. 최종 목표는 이 CLI로 구글 드라이브의 자료를 사교원 자체 서버로 내려받은 뒤 구글 드라이브를 무료 요금제로 되돌리는 것이다.

작업 1: gws CLI 제작 (완료)

파이썬 표준 라이브러리만 사용해 단일 파일로 만들었다. 별도 설치(pip)가 필요 없고, 기존 skdata 와 같은 설계·출력 방식을 따른다.

항목값
실행 파일~/.local/bin/gws (심링크)
실체~/workspace/sakyowon-server/tools/gws.py (약 1,230줄)
설정 위치~/.config/gws/ — client.json(공용), tokens/<라벨>.json(계정별), default(기본 계정). 모두 권한 600
사용법 정본~/workspace/knowledge/references/gws-cli.md

제공하는 명령은 다음과 같다.

  • 드라이브: ls find tree info cat get put mkdir mv rm share
  • 문서·시트: docs read(구글 문서를 마크다운으로), sheets tabs|read|write|append
  • 지메일: mail list read draft send
  • 캘린더: cal list cal add
  • 계정: auth init|login|status|logout, account add|list|use|rm, whoami

특징은 세 가지다. 첫째, 인자에 구글 URL을 그대로 붙여넣어도 파일 ID를 스스로 뽑아낸다. 둘째, 계정이 여러 개인 상황을 전제로 만들어서 gws -a 망남 drive ls 처럼 계정을 골라 실행하거나 gws -a all mail list 로 등록된 모든 계정을 한 번에 훑을 수 있다(쓰기 명령은 계정 지정을 강제하여 사고를 막았다). 셋째, 위험한 동작에 제동을 걸었다. mail send 는 --yes 가 없으면 미리보기만 하고 멈추고, drive share 는 대상과 권한을 보여준 뒤 확인을 받고, drive rm 은 기본이 휴지통이며 완전 삭제는 파일 이름을 다시 입력해야 한다.

검증은 구글 API 응답을 흉내 낸 스텁으로 전 명령을 돌려서 했다. 목록·검색·문서 읽기·시트 표/CSV 출력·메일 목록과 본문·발송 미리보기·일정 조회와 등록·URL에서 ID 추출·시각 파싱·다계정 전환과 전체 순회가 모두 의도대로 동작했다. 다만 실제 구글 서버와의 통신은 아직 한 번도 하지 못했다(아래 미완료 1번).

작업 2: 구글 클라우드 콘솔 설정 (대부분 완료)

항목값
소유 계정망남 계정 (올망즐망)
프로젝트 이름gws-cli
프로젝트 IDgws-cli-509909
사용 설정한 APIDrive, Sheets, Docs, Gmail, Calendar (5종)
OAuth 동의 화면앱 이름 gws, 사용자 유형 외부, 게시 상태 테스트 중
OAuth 클라이언트이름 gws, 유형 데스크톱 앱
테스트 사용자사교원 지메일 23개 전부 등록 완료

받은 클라이언트 JSON은 D:\Users\User\Downloads\ 에 내려왔고, 이를 ~/.config/gws/client.json 으로 설치해 두었다(gws auth init 완료).

레슨

첫째, 구글 클라우드 콘솔은 2단계 인증이 켜진 계정만 들어갈 수 있다. 2025년 9월 30일부터 강제된 정책이다. 안 켜져 있으면 무슨 페이지를 열든 “Google Cloud 액세스 차단됨” 으로 튕긴다. 게다가 2단계 인증을 켠 직후에도 기존 로그인 세션은 그대로라서 계속 차단된다 — 로그아웃 후 다시 로그인해야 풀린다.

둘째, 계정이 많은 집에서는 “어느 계정에서 켰는가”를 먼저 확인해야 한다. 이번에 이사장님이 2단계 인증을 켠 계정과 브라우저가 콘솔에 쓰던 계정이 서로 달라서 30분을 허비했다. 구별법은 보안 페이지의 비밀번호 최종 변경일 과 복구 이메일 이다. 복구 이메일이 A라면 그 화면은 A의 것이 아니다.

셋째, 구글 콘솔 화면을 브라우저 자동화로 조작할 때 좌표 클릭은 신뢰하기 어렵다. 뷰포트 크기가 551×86 같은 값으로 고장 나 스크린샷과 실제 화면이 어긋나는 일이 있었고, 그 탭에서는 클릭이 전부 빗나갔다. 탭을 새로 열면 회복된다. 또한 화면 좌표계(스크린샷 프레임)와 페이지 CSS 좌표가 다를 수 있으므로, getBoundingClientRect() 로 얻은 좌표는 두 값의 비율로 환산해서 써야 한다. 버튼은 좌표보다 find 로 얻은 참조나 자바스크립트 .click() 이 안전했다.

넷째, 약관 동의 같은 체크박스는 자바스크립트 클릭이 먹지 않을 수 있다. Angular Material 컴포넌트라 DOM의 checked 값만 바뀌고 폼 모델은 그대로여서 “계속하려면 서비스 약관에 동의해야 합니다” 가 계속 떴다. 사람이 누르는 것과 같은 실제 마우스 클릭으로만 해결됐다.

다섯째, 테스트 상태의 OAuth 앱은 갱신 토큰이 7일마다 만료된다. 계정이 23개면 매주 23번 다시 로그인해야 한다는 뜻이라 사실상 못 쓴다. 프로덕션 게시가 선택이 아니라 필수다(미완료 2번).

여섯째, 클라이언트 보안 비밀번호가 화면에 뜬 상태로 스크린샷을 찍으면 그대로 남는다. 이번 세션 채팅에 한 번 노출됐다. 실제 피해는 없지만, 데스크톱 클라이언트를 새로 만들어 교체해 두는 편이 깔끔하다.

미완료

  1. 계정 로그인(토큰 발급) — 아직 0개. gws auth login 은 브라우저에서 계정을 고르고 “허용”을 눌러야 끝난다. 계정 비밀번호 입력은 데카가 하지 않으므로(정책), 이사장님이 크롬에 해당 계정으로 로그인해 두면 데카가 gws account add --label <라벨> 을 돌려 토큰을 받는다. 라벨은 ~/workspace/knowledge/references/사교원-구글계정-23개.md 의 표를 그대로 쓴다(대표·망남·연구소·stl·해남 등). 현재 크롬에 로그인돼 있는 계정은 망남·대표 두 개뿐이다.
  2. OAuth 앱 프로덕션 게시 — 데카가 준비하고 이사장님이 누름. 지금은 “테스트 중”이라 7일마다 재로그인해야 한다. 게시하려면 브랜딩 페이지에 애플리케이션 홈페이지·개인정보처리방침 링크·서비스 약관 링크와 승인된 도메인이 필요하다. sakyowon.co.kr 에 정적 페이지 두 장(개인정보처리방침, 이용약관)을 올리면 충족된다 — 데카가 만들어 올릴 수 있다.
  3. 구글 드라이브 자료 내려받기 → 무료 요금제 전환. 이사장님이 정한 다음 목표다. 계정 23개의 드라이브 자료를 사교원 자체 서버로 내린 뒤 유료 요금제를 해지한다. 용량·우선순위 파악부터 필요하며, 2022년 이전 사업 계정들은 미사용 2년 경과로 구글이 삭제할 수 있는 구간이라 회수가 급하다.
  4. OAuth 클라이언트 재발급 검토(선택). 위 레슨 여섯째 참조.
  5. gws.py 를 저장소에 커밋하지 않았다. 현재 sakyowon-server/tools/ 에 파일만 놓여 있다. 지미가 관리하는 캐노니컬 저장소라 데카가 임의로 푸시하지 않았다. 백업이 필요하면 커밋 여부를 정해야 한다.
  6. 위키 라이브 반영이 안 됐다. 이 핸드오버는 sakyowon-wiki 저장소에 커밋·푸시(97a1d2b1)만 된 상태다. npx quartz build 로 public/ 을 만들어 deka2026/sakyowon-wiki-site 에 올려야 wiki.poomasi.org 에 뜨는데, 이 서버(3호기 deka 계정)에는 node·npm·npx 가 설치돼 있지 않아 빌드를 못 했다. 다음 세션에서 node 가 있는 환경에서 빌드하거나, 지미에게 요청해야 한다.
