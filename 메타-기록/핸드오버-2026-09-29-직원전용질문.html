세션 요약

이사장님 지시로 사교원 직원만 쓰는 질문 창을 만들어 라이브에 올렸다. 직원이 무엇이든 물으면 사교원 로컬 서버에 있는 자료(개인정보를 지운 사본)에서 근거를 찾아 주고, 그 근거로 NIPA 고성능컴퓨팅 엔진(H200 · EXAONE-LoRA) 이 답과 문서를 쓴다. 문서는 한글(.hwpx)로 내려받는다. 같은 세션에서 이사장님 임시 비밀번호를 넣고 직원 계정 다섯을 만들었으며, 사업별 칸막이는 두지 않기로 확정했다(망남 담당이 양양을, 양양 담당이 망남을 묻는다).

주소: https://sakyowon.co.kr/staff/ — 사교원 홈페이지 상단 「🔒 직원전용」 단추와 왼쪽 메뉴, 허브 첫 화면 「직원 전용」 칸에서 들어간다. 검색엔진에는 잡히지 않게 막았다.

1. 만든 것

화면 — 레포 deka2026/deka2026.github.io

  • 새 파일 staff/index.html(약 27KB, 바닐라 JS). 커밋 e1a60e6(첫 판) · 521789c(비밀번호 바꾸기).
  • 네 갈래: 질문하기 · 문서 만들기 · 내 문서함 · 자료·엔진.
  • 화면을 아펙스(sakyowon.co.kr)에 둔 까닭은 로그인과 권한이 사교원 API에 있고 그게 같은 오리진이기 때문이다. home.sakyowon.co.kr 의 「관리자 로그인」은 아직 프런트 목업이라 권한 판정을 맡길 수 없다.
  • robots.txt 에 Disallow: /staff/ 를 넣고 문서에 noindex 를 달았다.

메뉴 — 레포 haeory-cyber/sakyowon-site

  • 커밋 679adff. 상단 버튼과 사이드 메뉴 두 곳에서 https://sakyowon.co.kr/staff/ 로 보낸다.

매일 04:20 sakyowon-staff-kb.timer 가 다시 만든다. 새 파일로 만든 뒤 마지막에 갈아끼우므로 색인이 도는 동안에도 질문은 옛 색인으로 계속 답한다.

2. 얼개 — 왜 이렇게 갈랐나

브라우저 sakyowon.co.kr/staff  (쿠키 로그인, 권한 staff·admin)
   │  같은 오리진 /api/*  → www-src/server.py 프록시 → 127.0.0.1:8787
사교원 API (app_staff:app)
   ├─ staff_kb.search()   사내 색인에서 근거 조각 10개 (개인정보 삭제본)
   └─ staff_qa            질문+근거 → chat.solarshare.kr /api/v1/ask → 답·문서
  • 근거 찾기는 이 서버, 글쓰기는 고성능컴퓨팅. 엔진의 /api/v1/ask 는 자기 RAG(품앗이 위키)만 물고 있어 사교원 자료를 모른다. 그래서 발췌를 질문에 실어 보낸다. 실측으로 발췌를 그대로 따른다.
  • 문서는 세 번에 나눠 부른다 — plan(목차) → section(절마다) → finish(합치기). 클라우드플레어가 100초에 끊기 때문에 한 번에 문서 한 편을 쓰면 524로 죽는다. 절당 30~38초다.
  • 엔진이 쉬면 앤트로픽으로 몰래 물러서지 않는다(연동규격서 4-6). 쉰다고 말한다.

3. 개인정보를 막는 세 겹

  1. 자리 차단 — 허용목록 폴더만 읽는다. 다운로드·Telegram Desktop·카카오톡 같은 받은파일 더미와 명부·연락처·출장·급여·동의서·업무일지 따위 이름이 든 파일은 열지도 않는다.
  2. 본문 삭제 — 주민등록번호·휴대전화·전화·전자우편·계좌·카드·여권·API키, 라벨 뒤의 이름 (「성명: OOO」「담당자: OOO」), 그리고 전화번호 바로 앞의 이름까지 지운다.
  3. 조각 폐기 — 지운 자국이 4건 이상이거나 밀도가 높거나 「성명+연락처」·「결재+성명」 표 머리글이 보이면 그 조각을 통째로 버린다.

회원·신청·문의·상담·세션 DB 표는 아예 읽지 않는다. 서버 DB에서는 마을·월실적·회비· 자체사무·재무기초 같은 조직 단위 표만 문서로 만들어 넣는다.

🔴 남겨 둔 것: 「이주현 소장」「김일영 대표」처럼 직책과 함께 적힌 이름은 지우지 않는다. 공식 문서의 직책자 이름까지 지우면 사업 설명이 무너지기 때문이다. 이사장님께 판단을 여쭈어 둔 상태다.

4. 계정 (2026-09-29 확정)

아이디권한임시 비밀번호
kimilyoungadmin1111
망남1 망남2staff0000
양양1 양양2 양양3staff0000
  • 🔴 사업별 칸막이는 두지 않는다(이사장님 지시). staff·admin 이면 전체 자료를 묻는다. 조합원(coop)·연합회(federation)·일반(member)은 403. 사람별로 갈리는 것은 만든 문서함뿐이다.
  • 본인이 바꿀 수 있다 — 화면 위 「비밀번호」 단추. 새 비밀번호는 서버 규칙상 8자 이상이고, 바꾸면 다른 기기 로그인은 전부 끊긴다.
  • 임시 비밀번호를 쓰는 동안 빨간 안내줄이 뜬다. 판정은 서버가 한다(/api/staff/status 의 temp_password) — 화면에 임시 비번 목록을 적어 두면 남이 보고 남의 계정을 연다.
  • 이사장님 옛 비밀번호는 PBKDF2 단방향 해시라 서버도 모른다. 그래서 새로 넣었고 기존 세션 2개를 끊었다.

6. 레슨 (자세한 것은 knowledge/lessons 로)

  1. 🔴 app.py 에 직접 덧붙이지 마라. 라우터를 끝에 붙였는데 같은 시각 다른 작업이 그 파일을 통째로 다시 쓰면서 오류 하나 없이 사라졌다(파일 크기만 늘어 있었다). app_staff.py 로 얹는 자리를 갈라 두면 app.py 가 어떻게 바뀌어도 이 기능은 산다.
  2. 🔴 hwp5txt 는 표를 통째로 떨군다. 본문이 표인 점검자료는 65바이트 빈 껍데기가 나와 색인에서 조용히 빠졌다(양양 자료 6건 전부). hwp5html 로 뽑아 태그를 걷으면 13,000자로 살아난다.
  3. 읽기용 sqlite3.connect 가 없는 파일을 만든다. 0바이트 색인이 생겨 「색인 있음」으로 오판했고, 색인 완료를 기다리던 감시 여섯이 한꺼번에 헛 신호를 받았다. 읽기는 mode=ro URI 로만 연다.
  4. pgrep -f "패턴"·pkill -f "패턴" 은 자기 셸도 센다. 기다림이 영원히 안 끝나거나(전자) 내 셸이 죽는다(후자, exit 144). 포트나 pid 로 하라.
  5. 개인정보 지운 자국이 다음 판정을 어지럽힌다. 「[성명 제외]」 안의 ‘성명’ 이 명부 표 머리글 규칙에 걸려, 이름 하나 지운 회의록이 통째로 폐기됐다. 판정은 자국을 걷어내고 한다.
  6. 엔진의 자기 RAG 가 늘 섞인다. 「사교원 자료만」 모드에서도 sources 에 품앗이 노드가 붙고, 답변에 「헌법 제1척추에 따라」 같은 남의 말투가 새어 나온 적이 있다. 본부에 no_rag 옵션을 요청할 것.
  7. 전체 재색인은 56분(문서 5,601건). 규칙만 고쳤을 땐 staff_kb.py repair(2분), 자료원 하나만 더할 땐 staff_kb.py add <이름>(수 초). 한 시간을 다시 기다리지 마라.

7. 미완료

  1. 직책과 함께 적힌 이름을 지울지 — 이사장님 판단 대기. 지우기로 하면 staff_kb.py 의 이름규칙 옆에 「이름+직책」 규칙 한 줄을 달고 repair(2분)면 끝난다. (데카)
  2. 문서함 공유 여부 — 지금은 만든 사람만 본다(관리자는 전부). 직원끼리 공유할지 미정. (이사장님 → 데카)
  3. 본부에 no_rag 옵션 요청 — 사교원 자료만 근거로 삼는 모드에서 엔진 자기 RAG 를 끄는 스위치. 연동규격서 v0.3 논의에 얹을 것. (데카 → 지미)
  4. 임시 비밀번호 교체 — 직원 다섯과 이사장님이 각자 8자 이상으로 바꿔야 한다. 화면 위 「비밀번호」 단추. (사람)
  5. 햇소자 시험계정 16개(t26*)가 실서버에 그대로 있다. 상시 운영 전에 지워야 한다. (데카)
  6. 검색 품질 — 낱말이 겹치는 정도로만 고르기 때문에 같은 질문도 표현을 바꾸면 다른 근거가 올라온다. 「망남 1차년도 5대 과업」은 문서 작성에서는 찾았는데 질문에서는 못 찾았다. 임베딩 검색으로 올리는 것은 다음 과제다. (데카)
