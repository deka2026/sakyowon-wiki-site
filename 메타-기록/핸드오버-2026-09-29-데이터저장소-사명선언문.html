핸드오버 2026-09-29 — 데이터 저장소 완도 B 배포, 사명선언문 한글본 재작성

세션 요약

이사장님의 “서버를 로컬로 변경했어, 확인하고 작업해” 지시로 완도 B 서버 상태를 실측하고, 9월 27일부터 밀려 있던 데이터 저장소 API를 직접 배포해 라이브까지 검증했다. 이어 2024년 공증 정관 원본을 대조해 사명선언문을 만들었고, 한글 파일(.hwpx)에서 줄겹침 결함을 내가 다시 저질러 이사장님께 지적받은 뒤 정본 경로로 재작성했다. 그 과정에서 HWPX 스타일 id 순번 함정을 새로 발견했고, 지시받은 하단 중앙 쪽번호를 변환기에 상시 배선했다.

작업 1: 데이터 저장소 완도 B 배포 (완료)

9월 27일에 만들어 레포에 푸시해 둔 데이터 저장소가 화면만 살아 있고 API가 없는 반쪽 상태였다. 가비아 해지로 “이사장님이 SSH에서 붙여넣기” 경로가 사라졌고, 이제 데카가 완도 B에 sudo가 있으므로 직접 배포했다.

발견한 문제는 레포와 서버가 서로 다른 방향으로 갈라져 있었다는 것이다.

데이터저장소mangnam 훅AI 로그인 게이트
서버 배포본 (1,329줄)없음있음있음
캐노니컬 레포 (1,975줄)있음없음있음
공개 미러 (1,959줄)있음없음없음

레포를 그냥 덮었으면 망남 협동조합 모듈(/api/mangnam/* 19경로)이 죽었을 것이다. 캐노니컬의 데이터 저장소 섹션 바로 앞에 mangnam_api 훅 블록을 끼워 병합했다(1,987줄).

  • 백업 app.py.bak_20260928_082304_predata
  • openpyxl 3.1.5 를 /opt/sakyowon/.venv 에 설치(엑셀 업로드에 필요)
  • 읽기 전용 키 SAKYOWON_DATA_READ_KEY 를 생성해 /opt/sakyowon/sakyowon-api.env(600)에 기록
  • 데카 설정 ~/.config/sakyowon/data.env(600) 배선 완료
  • 커밋: 캐노니컬 083491a(haeory-cyber/sakyowon-site), 미러 e3fd8aa(deka2026/sakyowon-server)

검증은 라이브까지 왕복했다. 키 없이 401, 읽기 키로 200, 읽기 키로 쓰기 시도는 401, 틀린 키 401. 실제 CSV를 올려 타입 자동추론(금액 → INTEGER)과 skdata tables·rows·sql 을 확인한 뒤 검증용 표는 삭제했다.

이제 https://sakyowon.co.kr/data.html 에서 엑셀을 올리면 표로 저장되고, 데카가 skdata 로 직접 읽는다.

작업 2: 정관 대조 — 사업구역에 전라남도가 있었다

2024년 3월 20일 공증 정관 원본(등부 2024년 제2704호)을 펼쳐 대조했다. 스캔본이라 텍스트 레이어가 없어 poppler-utils 를 설치하고 페이지를 이미지로 읽었다.

🔴 위키에 있던 HWP 정관과 공증본이 다르다.

제5조 사업구역
위키 HWP본대전·세종·충남·충북
공증본(2024.3.8 개정)대전·세종·충남·충북 · 전라남도

망남·완도 사업의 정관상 근거가 이 조문이다. 위키의 HWP는 개정 전 판이므로, 그 파일을 근거로 삼은 문서가 있으면 손봐야 한다.

그 밖에 확인: 제정 2020.12.29 창립총회 / 1차 개정 2024.3.8 제5차 정기총회 / 주사무소 대전광역시 서구 관저중로 80번길 8, 3층.

작업 3: 사명선언문 — 세 가지 형태

정관에서 뽑아 여섯 절로 짰다. 모든 문장에 조문 근거를 달았다. 여섯째 절 “우리가 하지 않는 일”(정치 관여 금지·가입 차별 금지·배당 금지·공개 의무)이 이 문서의 뼈대다. 사회적협동조합의 정체성은 대부분 금지 조항에 들어 있다.

  • 위키 content/코어법인/사교원_사명선언문.md — 한글 변환에 맞게 고쳐 썼다(아래 작업 4)
  • 웹페이지 https://claude.ai/artifact/PtsLCrTn428ZwrtoBJVsh8 (비공개, 공유는 이사장님이)
  • 한글 D:\법인 문서방\사회혁신교육원_사명선언문.hwpx + .pdf + .md

작업 4: 🔴 HWPX 줄겹침을 내가 다시 저질렀다

이사장님이 한글에서 열어 긴 문단이 한 줄에 겹쳐 찍히는 것을 잡으셨다. 원인은 9월 28일에 이미 기록돼 있던 것과 똑같았다 — 내가 XML을 손으로 짜면서 <hp:linesegarray> 를 문단마다 하나씩 넣었다.

정본 변환기 ~/workspace/tools/md2hwpx.py 를 두고 직접 짠 것이 근본 잘못이다. 그 변환기는 애초에 linesegarray 를 넣지 않는다. 상세는 핸드오버 2026-09-28 사명선언문 HWPX 레이아웃 참조.

재작성은 정본 경로대로 갔다. md2hwpx.py → hwpx_house_rules.py → 쪽번호 → hwpx-고침 --점검.

마크다운도 한글 변환에 맞게 고쳤다. 제목 중복 제거, 조문 근거를 별도 문단으로 분리, 목록을 표로 전환, **굵게** 제거(템플릿이 바탕체로 바꿔 본문보다 작아 보였다).

작업 5: 🔴 새로 발견 — HWPX 스타일 id 는 순번을 이어야 한다

집 규칙인 첫 줄 들여쓰기가 파일에는 들어갔는데 화면에 안 나왔다.

<hh:paraPr id="200"> 을 새로 붙이고 문단 44개가 가리키게 했는데 한글이 무시했다. id="41"(기존 최대 40의 다음 순번)로 바꾸자 즉시 먹었다.

한글은 paraProperties·charProperties 목록을 id 가 아니라 순번(배열)으로 읽는다. 목록 밖 번호는 오류도 없이 기본값으로 떨어진다. 새 항목은 max(기존 id) + 1 로 붙이고 itemCnt 도 함께 올린다.

판정은 눈으로 훑어서는 놓친다(실제로 처음에 놓쳤다). PDF 좌표를 재야 한다 — pymupdf 로 줄 bbox[0] 을 찍어 첫 줄 89.1 / 이어지는 줄 65.1 이면 먹은 것, 전부 65.1 이면 안 먹은 것이다.

작업 6: 하단 중앙 쪽번호 — 상시 배선 (완료)

이사장님 지시로 만드는 모든 문서에 하단 중앙 쪽번호를 넣는다.

  • 새 도구 ~/workspace/tools/hwpx_pagenum.py (제자리 수정, 멱등)
  • ~/workspace/tools/md2hwpx.py 마지막 단계에 자동 호출로 배선 — 마크다운→한글 경로는 이제 자동이다
  • 남의 도구가 만든 hwpx 에만 따로 돌린다
  • 원리: 쪽번호는 구역 첫 문단의 컨트롤이다. secPr 을 품은 run 바로 뒤에 <hp:run><hp:ctrl><hp:pageNum pos="BOTTOM_CENTER" formatType="DIGIT" sideChar="-"/></hp:ctrl></hp:run> 를 끼운다. 결과는 - 1 - 꼴.
  • 검증: 3쪽 모두 x중심 297.4~297.6 vs 쪽폭중심 297.5

레슨

  1. 정본 도구가 있으면 그것을 써라. 줄겹침은 새 사고가 아니라 이미 기록된 사고의 재발이었다. 기억에 「이 함정이 있다」고만 적혀 있으면 부족하고, 「정본 경로는 이것이다」를 먼저 찾아 그대로 타야 한다.
  2. “파일에 썼다”는 검증이 아니다. 한글이 그 값을 실제로 쓰는지가 검증이다. 서식 변경은 XML grep 이 아니라 PDF 좌표나 렌더 이미지로 확인한다.
  3. PDF 로 검수를 갈음하지 마라 — 9월 28일 교훈이 그대로 유효하다. 다만 linesegarray 가 0인 파일은 한글이 직접 흘리므로 한글 COM 이 낸 PDF 가 편집 화면을 대표한다.
  4. 레포와 서버가 갈라져 있을 수 있다. 서버에서 install-on-server.sh 류로 직접 붙인 모듈은 레포에 없다. 배포 전 양쪽을 기능 단위로 대조한다.
  5. Cloudflare 뒤에서는 파이썬 기본 UA 가 막힌다. skdata 가 403 error code 1010 으로 죽었다. 이 도메인에 붙는 파이썬 도구는 전부 User-Agent 를 넣어야 한다.

미완료

  1. 위키 HWP 정관 교체 — 자산기반-사회연대경제/_로컬리스트-원본/01 사회혁신교육원 사회적협동조합_정관.hwp 는 2024년 개정 전 판이다(전남 누락). 공증본 기준으로 갈아야 한다. 누가: 다음 데카 인스턴스, 이사장님 확인 후.
  2. 사명선언문 문안 확정 — 데카가 정관에서 읽어낸 해석이다. 조합의 목소리로 다듬을 곳을 이사장님이 짚어주시면 위키·웹페이지·한글 세 곳을 맞춘다. 누가: 이사장님 검토 → 데카 반영.
  3. 망남 집행내역 3개년 엑셀 업로드 — workspace/mangnam-jaryo-files 의 2023·2024·2025 xlsx 를 데이터 저장소에 올릴 후보다. 개인정보가 들어 있어 직원 전용으로 잡아야 한다. 누가: 이사장님 승인 후 데카.
  4. 공개 미러의 tools/gws.py — deka2026/sakyowon-server 는 공개 레포다. 구글 연동 코드를 올릴지는 판단이 필요해 이번 푸시에서 뺐고 추적 안 된 상태로 남아 있다. 누가: 이사장님 판단.
