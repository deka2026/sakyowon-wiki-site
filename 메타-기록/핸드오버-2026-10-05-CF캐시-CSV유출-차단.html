세션 요약

안심협동조합이 사교원 근태 판(work.sakyowon.co.kr)을 옮겨 쓰다가 구멍을 하나 찾아 10-04 제보했다. 코드의 관리자 권한 검사는 멀쩡한데, 클라우드플레어가 .csv 확장자 응답을 기본으로 캐시해서, 관리자가 CSV 를 한 번 내려받으면 그 사본이 엣지에 4시간 남고 그 뒤로는 로그인 없이 같은 주소에서 열린다는 내용이었다. 10-05 완도 B호기에서 재현해 사실로 확인했고, 같은 구멍이 인사기록(급여대장·인사명부 CSV)과 홈페이지 아펙스 API(신청자 CSV)에도 있는 것을 찾아 FastAPI 앱 여섯 모두에 캐시 금지 미들웨어를 넣고, 클라우드플레어 캐시를 전부 비우고, 서비스 유닛의 프록시 신뢰 범위를 좁혔다. 안심 쪽은 우리 서버를 만지지 않고 결과만 알려 달라고 했다.

작업 1 — 재현 (10-05)

  • 방법: 근태 DB sessions 표에 임시 관리자 세션 토큰을 직접 넣고, 기록이 없는 과거 날짜 범위의 CSV 주소를 그 쿠키로 한 번 부른 뒤, 쿠키 없이 같은 주소를 다시 불렀다. 시험 뒤 임시 토큰은 바로 지웠다.
  • 결과: 첫 호출은 200 MISS, 쿠키 없는 두 번째·세 번째 호출은 200 HIT 였다. 제보가 맞다.
  • 같은 구멍이 있던 자리 셋: 근태 /api/admin/export/{records,summary,requests}.csv(날짜 쿼리), 인사기록 /api/export/pay.csv·people.csv(주소가 고정이라 더 위험), 아펙스 /api/applications.csv.
  • 재현 시점에 엣지에 담겨 있던 것은 시험으로 넣은 빈 CSV 뿐이었고 그것도 퍼지로 지웠다. 그 전 실제 노출 여부는 알 수 없다(클라우드플레어 무료 플랜은 캐시 로그가 없다).

작업 2 — 고친 것

  1. 캐시금지 미들웨어 — /opt/sakyowon/{work,hr,server,gw,talk,family}/app.py 의 app = FastAPI(...) 바로 아래. /api/* 응답에 Cache-Control: no-store, no-cache, private, max-age=0, Pragma: no-cache, Vary: Cookie 를 붙인다. 핸들러가 Cache-Control 을 직접 정한 경우(가족메신저 사진의 private 장기캐시)만 그대로 둔다. 엔드포인트별로 안 고친 이유는 빼먹을 자리를 안 만들기 위해서다. 아펙스는 Flask 프록시(www-src/server.py)가 상류 헤더를 그대로 넘기므로 상류(sakyowon-api, 8787)에 넣는 것으로 충분했다.
  2. 클라우드플레어 존 전체 퍼지 1회(API, ~/.config/cf/sakyowon-www.env 토큰).
  3. 프록시 신뢰 범위 — sakyowon-{work,hr,gw,talk,family}.service 의 --forwarded-allow-ips='*' 를 127.0.0.1 로. cloudflared 가 같은 WSL 에서 돌아 원점 접속은 전부 127.0.0.1 이다. '*' 면 X-Forwarded-For 맨 앞 값을 믿게 돼 로그인 스로틀 키를 요청마다 바꿔 넣을 수 있었다. 좁힌 뒤에도 접속 로그에 실제 공인 IP 가 찍히는 것을 확인했다.
  4. 서비스 여섯 재시작, 전부 active.
  5. 백업: ~/workspace/backups/cache-fix-20261005/(앱 여섯 원본 + 유닛 다섯).

작업 3 — 검증 (라이브, 클라우드플레어 경유)

  • 근태: 새 날짜 범위로 인증 호출 200 + cache-control: no-store + cf-cache-status: BYPASS, 무인증 호출 401 + BYPASS.
  • 인사기록 CSV 둘, 아펙스 신청자 CSV: 무인증 401 + BYPASS.
  • 그룹웨어·의정소통·가족메신저 /api/*: no-store 헤더 확인, DYNAMIC.
  • 퍼지 뒤 재현에 썼던 옛 주소도 401 + BYPASS.

레슨

  • 캐시 여부는 확장자가 정하고, 캐시는 인증 앞에 선다. 세션·권한 코드로는 영원히 못 잡는 자리다. 새 API 앱은 첫 줄에 캐시금지 미들웨어부터.
  • 판정 순서가 결과를 바꾼다. 캐시가 비어 있으면 401 이 나와 안 새는 것처럼 보인다. 반드시 ①인증으로 한 번 받고 ②무인증으로 같은 주소. 고친 뒤 확인은 새 쿼리로 — 옛 주소는 담긴 사본이 나와 안 고쳐진 것처럼 보인다.
  • 정본: knowledge/lessons/CF캐시가-인증을-비켜간다-api-no-store.md. 메모리 「클라우드플레어 함정」 6번으로도 넣었고, geuntae-ops·hr-ops 스킬에 「미들웨어 지우지 말 것」 한 줄씩 넣었다.

미완료

  1. (이사장님) 안심협동조합에 결과 답신. 세션 보고에 붙여 둔 답신 문안을 그대로 보내면 된다.
  2. (이사장님 결정) 연가 기본값 15일. 1년 미만 직원에겐 법정(월 1일·최대 11일)보다 많고 3년차 이상에겐 가산분만큼 적다. 안심은 입사일로 근로기준법 제60조 권고값을 화면에 띄우고 적용은 사람이 누르게 했다. 원하시면 데카가 같은 방식으로 붙인다. 지금은 코드가 정하지 않는 쪽 그대로다.
  3. (데카) 아펙스 API(sakyowon-api, 8787)는 --proxy-headers 없이 떠서 클라이언트 IP 가 늘 127.0.0.1 로 잡힌다. 로그인 스로틀이 전체 하나로 묶이는 셈이다. 이번 건과 별개라 손대지 않았고, 손댈 때는 --proxy-headers --forwarded-allow-ips=127.0.0.1 둘을 함께 넣는다.
  4. (데카, 새 앱 만들 때마다) 캐시금지 미들웨어를 첫 줄에. 유닛엔 --forwarded-allow-ips=127.0.0.1.
