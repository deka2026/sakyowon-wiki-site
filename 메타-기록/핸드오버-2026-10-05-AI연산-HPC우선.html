세션 요약

이사장님이 “사교원 서버에서 하는 모든 작업 중 연산은 고성능컴퓨팅 시스템을 활용하되, 개인정보와 관련된 내용만 고성능컴퓨팅으로 넘어가지 않도록 하라”고 지시하셨다. 서버의 AI 호출 지점을 모두 찾아, 공용 모듈 하나(/opt/sakyowon/hpc_route.py)를 거치도록 바꿨다. 기본은 NIPA H200 엔진이 처리한다. 처음에는 개인정보가 보이는 요청을 기존 경로(Anthropic 직통)로 돌렸으나, 15:30 이사장님 결정으로 개인정보가 든 요청은 거절하고 엔진 장애 때 Anthropic 폴백은 유지하도록 바꿨다(작업 4). 앱 네 개(사교원 API·그룹웨어·의정소통·홈페이지)에 붙였고 라이브 서버에서 기능별로 시험해 확인했다.

작업 1 — 전수 조사

AI를 부르는 곳은 다음과 같았다. 타이머·크론 작업(데카보고, 지미답장감시, e나라도움 갱신알림)에는 AI 호출이 없었다.

  • 사교원 API(/opt/sakyowon/server/app.py, 포트 8787): /api/ai(햇소자 서류 생성·검토·법령 탭, Anthropic 직통 스트림), /api/ai/chat(상담 탭, 원래 엔진), /api/translate(Anthropic), /api/consult/request(원래 엔진), 직원전용 질문 /api/staff/*(원래 엔진)
  • 그룹웨어(/opt/sakyowon/gw/app.py): 메일 초안, 월간보고 AI 칸 — Anthropic
  • 의정소통(/opt/sakyowon/talk/app.py): 질문, 서식 고르기, 문서 작성, 분량 맞춤 — Anthropic
  • 홈페이지(/opt/sakyowon/home/server.py): LONLO 챗, 번역 — Anthropic

작업 2 — 공용 모듈 hpc_route.py

  • 연산(지시, 입력, 앱=, 용도=, 대안=) 하나가 개인정보 판정, 엔진 호출, 재시도, 폴백, 기록을 모두 맡는다.
  • 가리기(글) 는 답에 값이 필요 없는 질의에서 개인정보를 「(생략)」으로 지운다. 상담 탭과 직원전용 질문에 쓴다.
  • 감지 항목: 주민·외국인등록번호, 여권·면허·카드·계좌번호, 휴대전화·전화, 전자우편, 아파트 동·호 주소, 건강정보 낱말, 비밀번호·API 키, 그리고 「성명」「담당자」「참석자」「받는 사람」 같은 라벨 뒤의 사람 이름. 기관명(끝이 청·과·팀 등이거나 넉 자 낱말)은 이름으로 보지 않는다.
  • 사진·PDF 첨부는 엔진이 읽지 못하고 토지대장 소유자 같은 정보가 실리므로 늘 기존 경로로 보낸다.
  • 엔진이 응답하지 않거나 「근거 없음」을 두 번 내거나 JSON 모양이 아니면 기존 경로로 폴백한다. 환경변수 HPC_FALLBACK=0 이면 폴백하지 않는다. 상담 탭은 연동 규격서에 따라 원래대로 폴백하지 않는다.
  • 기록은 /opt/sakyowon/data/hpc_route.jsonl 에 남고 본문은 적지 않는다(앱, 용도, 경로, 개인정보 종류, 글자 수, 처리 시간, 요청 번호만 적는다). 경로 값은 hpc, hpc-masked, refused(개인정보 거절, 작업 4 이후), local(이미지 첨부), fallback, fail 여섯 가지다.

작업 3 — 앱별 배선

  • 사교원 API: app.py 는 고치지 않았다(다른 작업이 통째로 다시 쓰는 일이 있었다). 새 파일 server/hpc_override.py 가 /api/ai·/api/ai/chat·/api/translate 경로를 떼어 내고 다시 달며, app_staff.py 끝에서 불러온다. /api/ai 스트림은 엔진 답을 Anthropic 스트림 모양으로 한 번에 흘리고, 기다리는 동안 15초마다 ping 을 보내 클라우드플레어 100초 제한을 넘긴다. 직원전용 질문은 staff_qa.py 의 _엔진() 에 가리기를 더했다.
  • 그룹웨어: _anthropic() 을 HPC 라우터로 감싸고 기존 직통 함수는 _anthropic_direct() 로 이름을 바꿨다.
  • 의정소통: _연산() 도우미를 만들어 질문·서식 고르기·문서 작성·분량 맞춤 네 곳을 바꿨다.
  • 홈페이지: claude() 를 감싸고 기존 함수는 _claude_direct() 로 이름을 바꿨다.
  • 백업은 바꾼 파일마다 옆에 *.bak_20261005_prehpcroute 로 남겼다. 서비스 4개는 재시작했고 모두 200으로 응답한다.

시험 결과(라이브)

  • 개인정보가 없는 요청은 전부 고성능컴퓨팅이 처리했다: 홈페이지 번역·LONLO 챗, 사교원 API 번역, 햇소자 이사회 회의록 생성, 그룹웨어 메일 초안(받는 사람이 군청 부서)·월간보고 JSON, 의정소통 질문·서식 고르기·5분발언 원고(3,280자, 37초)·분량 맞춤.
  • 개인정보가 있는 요청은 고성능컴퓨팅으로 가지 않았다: 전화번호가 든 번역, 참석자 이름이 든 창립총회 회의록, 이메일 주소가 든 메일은 기존 경로로 돌았다. 상담 탭에 휴대전화 번호를 넣은 질문은 번호를 지운 뒤 엔진이 정상 답변했다.

작업 4 — 개인정보는 거절, 폴백은 유지 (15:30 결정)

  • hpc_route.연산() 이 개인정보를 찾으면 개인정보거절 예외를 던진다. 어디로도 보내지 않고, 사용자에게 「개인정보(종류)가 들어 있어 AI 처리를 하지 않습니다. 해당 내용을 지우거나 「OOO」처럼 바꾼 뒤 다시 요청해 주세요.」가 뜬다.
  • 앱별 응답: 햇소자 /api/ai 는 422(스트림이면 error 이벤트), 그룹웨어·의정소통은 422 의 detail, 홈페이지 LONLO 챗은 답 자리에 안내문. 세 화면 모두 서버 문구를 그대로 띄우는 것을 코드에서 확인했다.
  • 번역(홈페이지·사교원 API)은 거절 때 원문을 번역 결과로 돌려준다(refused: true). 홈페이지 화면(translateToKorean)은 서버가 실패하면 MyMemory 공용 번역 API로 다시 보내는데, 문의 양식은 이름·연락처까지 번역에 넘기기 때문이다.
  • 엔진 장애·「근거 없음」 2회·모양 불량 때의 Anthropic 폴백은 그대로다. 시험 중 실제로 「근거 없음」 → 폴백이 한 번 일어난 것을 기록에서 확인했다.
  • 라이브 시험: 연락처가 든 번역 2건은 원문 반환, 이메일이 든 LONLO 챗·메일 초안과 이름이 든 회의록(스트림·일반)은 거절, 일반 번역·회의록은 정상 처리.
  • 백업은 *.bak_20261005_prerefuse.

레슨

  • 엔진에 질문만 주면, 엔진 자체 자료(햇빛소득마을)와 맞지 않는 주제는 「근거 없음」으로 빈 답을 낸다. 지시와 입력을 「[지시]…[자료]…」 꼴로 묶어 주면 그 자료를 근거로 삼아 답한다.
  • 개인정보 자리에 「[휴대전화 제외]」 같은 표식을 넣으면 엔진이 질문을 이상하게 보고 물러선다. 「(생략)」으로 바꾸면 정상 답이 나온다.
  • 라벨 뒤 이름 규칙은 기관명(완도군청)을 이름으로 잘못 잡았다. 넉 자 낱말과 기관 끝말을 제외해 고쳤다.
  • 의정소통 앱을 시험용으로 따로 띄우면 텔레그램 수신 루프가 함께 떠서 실서비스와 409 충돌을 낸다. 시험은 짧게 끝낼 것.
  • 엔진 draft·review 경로는 아직 없다(404). 규격서상 10월 1주 예정이었다.
  • 서버가 거절을 「실패」로 돌려주면 화면이 다른 외부 서비스로 다시 보내는 일이 있다(홈페이지 번역 → MyMemory). 거절을 넣을 때는 프런트의 실패 처리부터 읽어야 한다.
  • 여러 세션이 같은 public/ 에 동시에 위키를 빌드하면 산출물이 반쪽이 되고, 그것을 올리면 공개 위키 파일이 무더기로 사라진다(14:17~14:20 실제로 555개 → 27개, 다른 세션의 전체 재빌드로 587개 복구).

미완료

  1. 이사장님 결정: 엔진 장애 때 폴백 — 15:30 결정: 유지한다.
  2. 이사장님 결정: 개인정보 처리 — 15:30 결정: 거절한다. 개인정보가 보이면 HPC·Anthropic 어디로도 보내지 않고 「개인정보가 들어 있어 AI 처리를 하지 않습니다」 안내를 돌려준다(기록 route refused). 번역은 거절 시 원문을 그대로 돌려준다 — 실패로 돌려주면 홈페이지 화면이 MyMemory 공용 번역 API로 다시 보내기 때문이다. 이미지 첨부는 여전히 Anthropic으로 간다(엔진이 못 읽음) — 이것도 막을지는 미결.
  3. 데카: 본부가 draft·review 를 열면 햇소자 /api/ai 를 그 경로로 옮긴다.
  4. 데카: GPU 실적 「사교원 서버발」 칸 집계에 hpc_route.jsonl 의 처리 시간을 더한다(consult_reports, /api/staff/usage 와 함께).
  5. 데카: 라벨 없이 문장 속에 섞인 이름은 감지하지 못한다. 실제 기록에서 오탐·미탐을 살펴 규칙을 다듬는다.
