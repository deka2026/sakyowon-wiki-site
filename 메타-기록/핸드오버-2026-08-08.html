세션 요약

이날 세션은 두 갈래였다. ①시민주권경제 공론장 발제문에 수상태양광 확산 후보지의 시군별 현황과 단계별 소요 예산 두 절을 신설해 보완했다. ②사교원 계열 사이트의 도메인을 sakyowon.co.kr로 통합하는 작업을 시작해, GitHub Pages 계열은 완료했고 본부 서버 서빙 사이트(본진·bid·mangnam)와 서남해 관광은 Cloudflare 네임서버 이전 방식으로 진행 중이다(사람 액션 대기).

작업 1 — 공론장 발제문 보완 (완료)

  • 레포/파일: sakyowon-site, docs/공론장_발제문_시민주권경제_수정안_20260806.md (커밋 a4b4902, 이후 도메인 커밋 6227e44에 리베이스로 포함)
      1. 수정안(1장=원전 논증, 2장=공동체자산형성 사업 구조)을 바탕으로 2-4 후보지 시군 현황과 2-5 단계별 소요 예산 두 절을 신설. 기존 2-4(시민기금·펀드)는 2-6으로 밀림.
  • 핵심 계수 검증: 계획서의 “영암호 343MW·영산호 277MW·주암호 264MW”가 만수면적 × 10%(수면 사용) × ha당 0.8MW로 정확히 재현됨을 확인하고, 이 계수를 후보지 표 전체에 일관 적용했다. 영암호 42.86㎢·금호호 23.3㎢·나주호 780ha·고흥호 745ha·해창만호 500ha 등 만수면적은 웹 자료(디지털영암문화대전, 한국민족문화대백과 등)로 검증.
  • 예산 산정 근거: 확정 계획인 시범사업(24MW=757.4억)에서 역산한 MW당 31.6억 원(ESS·마이크로그리드·공동체 형성 포함)을 표준 단가로 삼아 3단계(시범 24MW→확산 150MW→본격 776MW, 누적 950MW=약 2조 4,200억)로 산정. 재원 30/20/35/15 분담을 단계별 표로 제시.
  • hwpx 원본은 이전 판 장 구성(1장=공동체자산형성)이라 최신 작업본인 md 수정안에 반영했다. hwpx 기준으로는 1-3절 뒤 위치.
  • 미확정: 117개소 전체 목록·확정 만수면적은 농어촌공사 RIMS·WAMIS 데이터로 후속 확정 필요. 2·3단계 물량/단가절감률은 표준가정 추정치.

작업 2 — 사교원 도메인 통합 sakyowon.co.kr (일부 완료, 일부 대기)

완료: GitHub Pages 계열 → 경로 방식

  • 방법: 허브 레포 deka2026/sakyowon-hub를 deka2026/deka2026.github.io(유저 사이트)로 rename. 이 한 번으로 같은 계정의 모든 프로젝트 사이트가 sakyowon.co.kr/<레포>/로 서빙되고, 옛 deka2026.github.io/<레포> 주소는 GitHub이 자동 301. DNS 추가 작업 불필요.
  • rename 직후 Pages가 errored 떠서 gh api -X POST repos/deka2026/deka2026.github.io/pages/builds로 재빌드 → built. 각 로컬 레포의 git remote도 새 URL로 갱신함.
  • 링크 일괄 교체(옛 도메인→sakyowon.co.kr, 허브 링크는 루트로): 허브, academy-site, teamlearning-site, mangnam-site, mangnam-coop, mangnam-vitality(소스 + gh-pages 배포브랜치), sakyowon-site(index·index-legacy·admin). admin.html 수정 후 admin-smoke PASS 5건 확인 후 푸시.
  • 제외: 연대지능 위키 카드는 wiki.poomasi.org 유지(본부 위키). sakyowon-wiki 레포의 quartz baseUrl은 미변경(현재 deka2026.github.io/sakyowon-wiki이지만 301로 정상 동작).
  • 라이브 검증: 7개 사이트 전부 200, 옛 도메인 잔존 0건.

대기: 본부 서버 서빙 사이트 → 네임서버 이전 방식(2안)

  • 경로 방식이 불가한 이유: sakyowon.co.kr apex는 GitHub Pages가 통째로 받아 리버스 프록시 불가. 본부/외부 호스팅 서비스는 서브도메인으로 붙여야 함.
  • 이사장님이 2안(네임서버를 본부 Cloudflare로 이전) 결정. sakyowon-site/JIMMY-DECA.md 요청 ⑩에 상세 기록.
  • 현재 DNS 레코드(2026-08-08 12:50 DoH 실측): A @ 185.199.108~111.153 4개 / CNAME www→deka2026.github.io / MX 10 mx1.hiworks.com·20 mx2.hiworks.com / TXT “v=spf1 include:_spf.hiworks.co.kr ~all” / 현 NS ns.gabia.co.kr·ns1.gabia.co.kr·ns.gabia.net.
  • 지미 봇 인스턴스는 CF API 토큰 접근 불가 → 서버의 지미 본편(후니님 Claude Code)이 처리해야 함. 지미가 후니님께 넘길 붙여넣기 블록을 회신함.
  • 목표 서브도메인: bid.sakyowon.co.kr→3200, mangnam.sakyowon.co.kr→비탈리티 포트, www.sakyowon.co.kr→본진(포트 8040), seonamhae.sakyowon.co.kr→서남해(CF 계정 확인 필요).

레슨

  • 가비아 네임서버 변경 위치: 도메인 [관리] → 상단 탭 「네임서버/DNS호스트/DNSSEC」. 1·2차에 CF 네임서버 입력, 3·4차는 비우기(기존 가비아 NS가 남으면 안 됨). 안전잠금 Off면 변경 가능, 기관이전 잠금(On)은 네임서버 변경과 무관하니 안 건드림.
  • 순서 엄수: CF 존 생성+레코드 입력 완료 → CF 네임서버 회신 → 그제서야 가비아에서 네임서버 변경. 존 준비 전 네임서버부터 바꾸면 메일(hiworks)·사이트가 몇 시간~하루 끊긴다. MX/SPF/DKIM 등 메일 레코드 누락은 치명적이라 가비아 DNS 화면 스크린샷으로 대조 필수.
  • GitHub Pages 유저사이트 rename 트릭: 프로젝트 사이트 여럿을 한 도메인 하위 경로로 묶을 때, 허브 레포를 <계정>.github.io로 rename하면 커스텀 도메인이 계정 전체 경로로 확장된다. rename 후 Pages errored면 builds POST로 재빌드.
  • 수상태양광 용량 추정 계수: 만수면적 × 10% × ha당 0.8MW. 계획서 3개 대상지 수치와 일치 확인됨. 재사용 시 이 계수 사용.
  • gh CLI는 여전히 ~/.local/bin/gh 전체 경로로 호출해야 함(시스템 gh 없음).

미완료 (다음 세션 이어서)

  1. [이사장님] 후니님께 (a)지미 붙여넣기 블록 (b)가비아 DNS 화면 스크린샷 전달 → 서버 지미가 CF 존 생성·레코드 입력 실행.
  2. [이사장님] 지미가 CF 네임서버 2개 회신하면 → 가비아 「네임서버/DNS호스트/DNSSEC」 탭에서 변경(1·2차 입력, 3·4차 비움). 변경 후 메일 수·발신 1통씩 최우선 테스트.
  3. [데카] 네임서버 반영·터널 연결 후 bid/mangnam/본진/서남해 개통 확인 → 허브 카드·각 사이트 링크를 서브도메인으로 교체·검증.
  4. [이사장님 결정 필요] 루트(sakyowon.co.kr)를 허브로 둘지 본진으로 둘지. 현재 계획은 허브=루트, 본진=www.. 바꾸려면 링크·색인 재작업 전에 결정.
  5. [데카/후속] 발제문 117개소 후보지 목록을 RIMS·WAMIS 실데이터로 확정.
  6. [지미 확인] seonamhae-grand.pages.dev가 본부 CF 계정 프로젝트인지 회신 대기.
