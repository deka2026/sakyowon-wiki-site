세션 요약

지미(본부)가 「시민재생에너지 AI 통합구조 제안」과 「햇소자↔품에 엔진 연동 규격서 v0.1」을 잇달아 전달했다. cre.sakyowon.co.kr 메인페이지 초안을 캐노니컬 레포로 옮겨 배포 직전까지 준비했고, 규격서가 데카에게 물은 4가지 질문에 코드 실측으로 답해 JIMMY-DECA.md에 회신했다. 지미 인스턴스가 둘(본편/그룹챗봇)로 나뉘어 있어 그룹챗용 답변은 별도로 자기완결형 텍스트로 다시 준비했다.

작업 1 — cre.sakyowon.co.kr 메인페이지 배포 준비

  • 지미가 sakyowon-site/cre/index.html에 넣어둔 초안을 검증(로컬 서빙, 태그 균형, 내부 앵커 전부 OK, /api/... 호출 없는 순수 정적 페이지, 디자인 가이드 부합) 후 캐노니컬인 sakyowon-hub(deka2026.github.io) 레포로 이전했다. sakyowon.co.kr이 이제 GitHub Pages가 아니라 가비아 자체서버(deploy-www.sh가 허브 레포를 통째로 복사)로 서빙되기 때문에, 옛 sakyowon-site 쪽에 남겨두면 실제로 배치되지 않는다.
  • sakyowon-hub: 526dbf2 — cre/index.html 추가.
  • sakyowon-site: 61f7220 — 중복 사본 제거 + Caddyfile에 cre.sakyowon.co.kr 정적 블록 추가.
  • sakyowon-server(공개 미러): 145f59a — 같은 Caddyfile 블록 동기화.
  • DNS 실측 결과 cre.sakyowon.co.kr A레코드가 아직 없다 (vitality.는 이미 있음, bid.도 아직 없음 — bid는 별도 대기 건).

작업 2 — 연동 규격서 v0.1 회신 (JIMMY-DECA.md)

지미가 규격서 9절에서 물은 4가지에 코드 실측(server/app.py, sunvillage.html, hatsoja/index.html)으로 답해 두 통(8982e21, 31b89eb)을 편지함에 남겼다.

  • 질문 1(서류 종류·항목): 생성 7종(회의록·마을총회의사록·창립총회의사록·진행보고서·공문·공고문·주민동의서) + 사업계획서 서식3 6항목 + 검토 8종(토지대장·건축물대장·계통연계검토의견서·탄소배출량검증인정서·KS인증서·정관·계약서·기타) + 법령상담 8종 + 수익리포트. 전부 sunvillage.html의 실제 AI 프롬프트에서 추출한 값이라 근거가 있다.
  • 질문 2(호출 빈도): 실서빙 캐노니컬 hatsoja는 /api/ai/chat 상담 1곳뿐(레거시 sunvillage의 서류엔진 5탭은 아직 hatsoja에 이식 안 됨 — 이게 이번에 잡은 중요한 전제 오류, 아래 “발견” 참조). rate limit·timeout 제안값 포함.
  • 질문 3(방화벽): 데카 격리 계정 권한 밖이라 확인 불가 — 서버 쪽 curl 한 줄 재요청만 남겨둠.
  • 질문 4(마을 익명키): villages.id(autoincrement)를 V-0031 형태로 파생 가능하나, DB 재생성 시 안 흔들리는 안정적 ref 컬럼 신설을 권고. 발급 주체(엔진 vs 사교원)는 지미 결정 대기.

발견 — 규격서 전제 오류

규격서 2·6절이 전제한 “AI 호출 두 곳”은 레거시 sunvillage.html 기준이다. 실제 sakyowon.co.kr/hatsoja로 서빙 중인 캐노니컬 hatsoja/index.html은 상담(/api/ai/chat) 하나뿐이고, 서류 초안·검토 AI는 아직 MOCK이다. 그래서 회신에 “③=ask를 상담탭에 먼저 붙이고, draft/review는 프런트 이식과 병행해야 실사용이 된다”는 순서 조정을 제안했다.

레슨

  • 지미는 인스턴스가 둘이다 — 본편(서버, JIMMY-DECA.md 읽음)과 그룹챗 봇(격리, 편지함 접근 불가로 추정). 그룹챗으로 온 요청에 편지함 회신만 믿으면 답이 안 닿을 수 있다. 이번엔 편지함 회신을 요약해 파일 경로 참조 없는 자기완결형 텍스트로 별도 준비해 이사장님이 그룹챗에 직접 붙여넣을 수 있게 했다. (project-jimmy-channel 메모리에 이미 있던 교훈, 이번에 재확인)
  • sakyowon.co.kr의 캐노니컬 콘텐츠 소스는 이제 sakyowon-hub(deka2026.github.io)다. sakyowon-site 레포는 옛 poomasi.org GCP 서빙용으로 남아있을 뿐이라, 새 정적 페이지를 받으면 그 위치에 두지 말고 허브로 옮겨야 실제로 배치된다. 지미가 파일을 sakyowon-site에 놓는 걸 전제로 편지를 보내니, 앞으로도 이 확인이 필요하다.
  • deploy-www.sh는 허브 레포를 통째로 루트 복사하므로, 허브 안에 새 폴더(cre/ 등)를 추가하기만 하면 스크립트 자체는 손댈 필요가 없다. 서브도메인으로 쓰려면 Caddy 블록만 추가하면 된다.

미완료 — 이사장님이 하셔야 할 일

  1. 가비아 콘솔에서 cre A레코드 추가 (1.201.116.225)
  2. DNS 반영 후 서버에서 Caddy 블록 반영 + bash /opt/sakyowon/src/deploy-www.sh 실행 (명령 전문은 세션 대화 또는 gabia-server-ops 스킬 패턴 참고)
  3. chat.solarshare.kr 아웃바운드 확인 curl 한 줄 실행 → 결과 지미에게 회신 (질문 3 닫는 조건)
  4. 서류 카탈로그 답변(질문 1)을 그룹챗에 직접 붙여넣기 — 편지함이 안 닿는 지미 인스턴스 대비
  5. 지미의 v0.2 반영 요청(문서 종류 확장·순서 조정·마을 ref 발급주체 확정) 회신 대기 — 데카 쪽 작업은 그 이후 착수
