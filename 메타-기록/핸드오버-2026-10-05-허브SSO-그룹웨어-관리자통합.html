세션 요약

2026-10-02부터 10-05까지 한 세션에서 이어 진행했다. 허브(sakyowon.co.kr) 통합계정 하나로 의정소통·정책지원관 지원시스템·인사기록·근태·그룹웨어에 들어가게 했고, 사교원 홈페이지 관리자 메뉴의 7월 모형(가짜 숫자)을 인사·회계·세무·자산 실데이터로 바꿨다. 사교원 그룹웨어(gw.sakyowon.co.kr)를 새로 세워 직원전용 질문을 그리로 옮기고, 정책지원관 지원시스템은 홈페이지 「연구실」 메뉴 아래로 옮기면서 의정소통 대화를 그 안으로 합쳤다. 끝으로 이사장 허브 아이디를 의정소통과 같은 이름으로 통일하고 임시 비밀번호를 발급했으며, 시험용 관리자 계정을 지웠다.

1. 허브 통합계정 SSO

  • 공용 모듈 /opt/sakyowon/hub_sso.py 를 만들었다. 허브 API(완도 B 127.0.0.1:8787)의 로그인·세션 확인을 중계하고, 허브가 .sakyowon.co.kr 도메인으로 심는 세션 쿠키 하나로 하위 도메인 앱들이 로그인 상태를 공유한다. 결과를 60초 기억하고, 로그아웃 때는 forget() 으로 지운다.
  • 붙인 앱: 의정소통·정책지원관 지원시스템(talk), 인사기록(hr), 근태(work), 그룹웨어(gw). 각 앱은 자기 로그인이 없을 때 허브 쿠키를 보고 사용자를 찾는다. 인사기록은 users.hub_username 으로 묶고, 근태는 허브 계정의 이름과 근태 명단 이름이 같아야 이어진다.
  • 허용 역할은 앱마다 다르다. 의정소통·인사기록은 관리자만, 근태·그룹웨어는 관리자와 직원.
  • 각 앱 원본은 app.py.bak_2026100x_* 로 남겨 두었다.

2. 사교원 홈페이지 관리자 — 모형에서 실데이터로

레포 haeory-cyber/sakyowon-site(index.html 한 장, 라이브 home.sakyowon.co.kr · sakyowon.poomasi.org). 서버 코드 /opt/sakyowon/home/server.py 는 git 밖이라 서버에서 직접 고친다.

  • 로그인: 아무 값이나 통과하던 모형 로그인과 데모 단추를 없애고 허브 계정 실제 로그인으로 바꿨다. 서버의 /api/auth/*·/api/admin/* 를 허브 계정 서버로 중계한다. 관리자·직원만 관리자 화면에 들어오고, 인사·회계·세무·자산은 관리자만 본다.
  • 인사: 인사기록 시스템의 명부·임원·급여 현황을 읽기 전용으로 보여 준다(/api/hr/* 중계). 주민번호 열람·CSV·감사기록은 막고, 명부도 연락처·주소·계좌·생년월일을 빼고 보낸다. 상세는 인사기록 화면으로 딥링크(#p=번호).
  • 회계·세무·자산: 데이터 저장소(/api/data, datasets.db)에 표 6개를 올렸다 — 재무제표 2019~2025, 양양 운영계좌 기장과 월별 집계(2026), 세무 신고 이력, 정기 세무 일정, 자산·비품·렌탈 대장. 적재 도구는 ~/workspace/tools/경영자료_가져오기.py(--apply 와 관리자 키 필요). 홈 서버 /api/fin/* 는 허브 관리자 세션일 때 해당 표만 읽기 전용으로 넘긴다.
  • 그룹웨어 메뉴: 관리자 메뉴 「그룹웨어」에 gw.sakyowon.co.kr 을 띄운다(직원·관리자 모두).
  • 비밀번호 변경: 관리자 사이드바에 「비밀번호 변경」을 넣었고, 임시 비밀번호로 들어오면 변경 창이 자동으로 뜬다.
  • 주요 커밋: 09bce7a(로그인·인사), d065b8b(회계·세무·자산), 2d106df(연구실 메뉴), 0062810(그룹웨어 메뉴), 3b29aff(로그인 단추 복구), a7ede8f(비밀번호 변경).

3. 사교원 그룹웨어 (gw.sakyowon.co.kr, 신설)

  • 코드 /opt/sakyowon/gw/(FastAPI, 포트 8794, sakyowon-gw.service, git 밖). 클라우드플레어 터널 호스트는 같은 폴더 개통.py 로 열었다.
  • 모듈: 홈, 직원전용 질문, 보고서·기획안 작성, 메일(AI 초안 → Gmail 작성창, 관리자는 대표 계정 받은편지함), 결재(기안 → 관리자 승인·반려, 대기 중 회수), 출퇴근·휴가, 관리자용 인사·회계·세무·자산, 정책지원관 지원시스템.
  • 직원전용 질문 화면의 정본이 /opt/sakyowon/gw/static/staff.html 로 바뀌었다. 허브 sakyowon.co.kr/staff/ 는 그룹웨어로 보내는 안내 페이지다. 색인과 엔진은 그대로 허브 서버에 있다.
  • 운영 정본은 groupware-ops 스킬.

4. 정책지원관 지원시스템 — 홈페이지 연구실로, 의정소통은 안으로

  • 홈페이지 사이드바에 「연구실」 묶음(연구자료 + 정책지원관 지원시스템)을 만들고, #/policy 화면에 talk.sakyowon.co.kr/system 을 띄웠다. 메뉴 번역 8개 언어.
  • talk 앱: 루트(/)는 /system 으로 보내고, 대화 화면은 /chat 으로 옮겼다. 시스템 안 「의정소통」 탭이 /chat?embed=1 을 띄운다. 로그인 안내는 시스템 안 로그인 폼으로 바꿨다.
  • 연대지능아카데미 사이트에는 원래 이 시스템 링크가 없었다. 허브 첫 화면 단추만 있었고, 홈페이지 연구실로 바꿨다.

5. 계정 정리

  • 의정소통의 검증용 손님 계정 하나를 지웠다(남긴 글 없음).
  • 이사장 허브 아이디를 의정소통 아이디와 같게 바꿨다. 계정 번호는 그대로라 햇소자 등 번호로 묶인 자료는 영향이 없다. talk.env 의 허브 아이디 대응표는 필요 없어져 비웠다.
  • 임시 비밀번호 발급 도구 /opt/sakyowon/server/임시비번.py 를 만들었다. 무작위 10자를 화면에 한 번만 보여 주고, 발급 해시를 temp_passwords 표에 적어 두며, 그 계정의 기존 세션을 모두 끊는다. 확인 API /api/auth/password-status 는 staff_qa.py 라우터에 있다(app.py 는 건드리지 않는다). 허브 통합 관리자·홈페이지 관리자·그룹웨어·직원전용 질문이 이걸 보고 변경 창을 띄운다.
  • 햇소자 부하시험 때 만든 시험 관리자 계정을 지웠다(세션 21개 포함). 직원전용 질문 사용 이력 4건은 남겼다. 지우기 전 허브 DB 백업은 /opt/sakyowon/data/ 아래 .bak_20261005_*. 햇소자 시험 계정 15개(회원협동조합·연합회)는 이사장 지시로 그대로 둔다.

6. 바로잡은 실수

  • 그룹웨어 탭 위치: 처음에 허브 admin.html 에 넣었는데, 그 페이지는 햇소자 사이트가 「통합 관리자」로 링크하는 공용 페이지라 햇소자에 그룹웨어가 붙은 것처럼 보였다. 홈페이지 관리자 메뉴로 옮기고 허브 쪽 탭은 뺐다.
  • 관리자 로그인 단추 먹통: 10-02 로그인 개편 때 옛 로그인 코드 구간을 통째로 갈아 끼우면서 그 앞에 있던 handleLoginBtn 함수까지 지웠다. 10-03 복구하고 회귀 시험을 넣었다.

레슨

  • 코드 구간을 통째로 갈아 끼울 때는 앞뒤 경계의 함수까지 같이 날아갈 수 있다. 바꾸기 전후 함수 이름 목록을 맞대고, 사라진 함수를 화면이 아직 부르는지 확인하라(knowledge/lessons/구간교체-함수유실-점검.md).
  • 허브 admin.html 은 사교원 전용이 아니라 관계 사이트 공용 「통합 관리자」다. 사교원 내부 기능은 홈페이지 관리자 메뉴에 둔다.
  • SSO 결과를 캐시하면 로그아웃 뒤에도 캐시 시간 동안 로그인된 것처럼 보인다. 로그아웃 경로에서 캐시를 지워야 한다.
  • 결산 재무제표 PDF 는 pypdf 의 layout 모드로 열 위치를 보고 당기·전기를 가른다. 손실 과목은 이름을 「이익」으로, 금액을 음수로 맞춘다. 2023년 PDF 는 이미지라 2024년 결산서의 전기 열에서 가져왔다(knowledge/lessons/결산재무제표PDF-파싱.md).
  • 시험은 임시 허브 계정을 만들어 서버 안(127.0.0.1)으로 돌리고 끝나면 지운다. 실계정 비밀번호는 쓰지 않는다.

미완료

  1. 이사장님: 받으신 임시 비밀번호로 한 번 로그인해 본인 비밀번호로 바꾸기(어느 화면이든 변경 창이 뜬다).
  2. 데카: 그룹웨어 다음 단계 — 직원별 메일함(계정별 구글 인증), 결재 첨부파일과 여러 결재선, 문서 작성 결과를 결재로 바로 올리기, 홈에 오늘 출근 현황.
  3. 데카: 홈페이지 관리자의 대시보드 KPI·SNS 발행·주문·문의 메뉴는 아직 7월 모형이다.
  4. 회계 담당·이사장님: 양양 운영계좌 기장의 미확인 거래(추가 출금 행의 시각·적요, 4월 13일 3건)를 확정하면 데카가 경영자료_가져오기.py --apply 로 다시 올린다.
  5. 데카: 근태 SSO 는 허브 계정 이름과 근태 명단 이름이 같아야 한다. 직원 허브 계정을 만들 때 근태 명단 이름과 맞출 것.
