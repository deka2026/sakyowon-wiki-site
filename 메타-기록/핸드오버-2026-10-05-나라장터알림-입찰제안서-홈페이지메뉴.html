세션 요약

이사장님 지시로 다섯 가지를 했다. 첫째, 나라장터에서 마감이 7~14일 남은 용역 공고 중 사교원 사업 성격에 맞는 것을 3일마다 찾아 공고문·과업지시서·제안요청서와 함께 텔레그램 「사교원 입찰 정보」 방에 올리는 자동 알림을 만들어 첫 발송까지 마쳤다. 둘째, 옛 입찰메이트 사이트를 없애고 그룹웨어 안에 「입찰 제안서」 기능을 새로 만들었다. 나라장터 공고 문서를 분석해 사교원 기업정보·수행실적·참여인력으로 정성제안서·정량제안서·입찰서류 초안을 한글(hwpx)로 만든다. 셋째, 홈페이지 메뉴를 소개·연구실·쇼핑·그룹웨어·문의 다섯 개와 하위 12개로 다시 짰다. 넷째, 쇼핑 아래 교육프로그램 3종과 비용 계산기·강의별 필요 진단을 넣었다. 다섯째, 법인 문서방 원본으로 중소기업확인서와 신용평가등급이 모두 유효함을 확인해 입찰 기업정보에 반영했다.

작업 1 — 나라장터 입찰 알림 (텔레그램 자동 발송)

  • 명령은 ~/.local/bin/나라장터알림이고, 터미널 탭에서 쓰는 영문 이름 g2b-notice를 함께 붙였다. 설정(키워드·제외어·방·기간)은 ~/.config/sakyowon/나라장터.json에 있다.
  • 자료는 공공데이터포털 「조달청_나라장터 입찰공고정보서비스」 API에서 받는다. 나라장터 웹사이트는 서버에서 직접 읽으면 브라우저 검사 화면으로 튕겨서 쓸 수 없었다. 인증키는 이사장님 개인 명의 공공데이터포털 계정으로 받았고(법인 명의 가입은 휴대폰 본인인증 때문에 막힘), 서버의 권한 600 파일에 들어 있다. 키 값은 어디에도 적지 않았다.
  • 조회는 개찰일시 기준으로 앞으로 15일 치 용역 공고를 한 번에 받고(약 3,400건), 공고명 키워드 점수(상 2점·중 1점, 기준 2점)와 제외어로 거른다. 마감 범위는 이사장님 지시로 최소 7일, 최대 14일이다.
  • 첫 판은 43건이 걸려 잡음이 많았다. 「역량강화」「아카데미」를 중요도 중으로 내리고 해외·PMC·취업·시스템개발·행사·홍보 등을 제외어에 넣어 10건으로 줄였다.
  • 첨부는 공고문·과업지시서·제안요청서만 골라 보내고, 같은 문서가 한글·PDF 두 벌이면 한글만 보낸다. 한 번 올린 공고는 다시 올리지 않는다. 내려받은 문서는 ~/workspace/data/나라장터/날짜/에 쌓인다.
  • 타이머 g2b-bid-notice.timer가 매일 09:20에 깨우고, 스크립트는 마지막 실행 뒤 3일이 지났을 때만 돈다. 첫 발송은 10월 5일 15:15에 공고 10건(글 21개, 파일 묶음 10개)으로 했다. 다음은 10월 8일이다.
  • 텔레그램 발송 명령 올려에 파일 첨부(--첨부)와 답장(--답장) 기능을 붙였다.
  • 이사장님이 입찰 전용 새 방을 만드셨다. 봇 메시지 수신은 의정소통 서버가 독점하므로, 그 서버의 수신 루프에 「봇이 들어가 있는 그룹 방 번호만」 기록하는 줄을 넣어 새 방을 자동 등록하게 했다(본문은 기록하지 않는다).

작업 2 — 입찰메이트 삭제, 그룹웨어 「입찰 제안서」 신설

  • 옛 입찰메이트(Next.js)는 주소가 이미 죽어 있었고 저장된 자료도 0건이었다. 서비스를 멈추고 자동 시작을 껐으며, 앱 폴더는 지우지 않고 ~/apps/_보관_bid-helper_20261005/로 옮겼다. 허브(sakyowon.co.kr) 첫 화면 카드와 관리자 목록에서 지웠다(허브 레포 커밋 4b5270d). GitHub 저장소는 남겨 두었다.
  • 새 기능은 그룹웨어 「업무 › 입찰 제안서」다. 코드는 /opt/sakyowon/gw/bid.py(API /api/bid/*)와 /opt/sakyowon/gw/static/bid.html이다. 그룹웨어는 git 저장소가 아니라 서버에서 직접 고쳤고, 고치기 전 사본(app.py.bak_20261005_prebid, static/index.html.bak_20261005_prebid)을 남겼다.
  • 흐름: 텔레그램에 올라온 공고를 고르거나 공고번호를 넣는다 → 나라장터에서 공고 정보와 첨부를 모두 받는다 → AI가 문서를 덩이로 나눠 평가 배점·제출서류·과업·자격·유의사항을 뽑는다 → 참여인력을 골라 정성제안서·정량제안서·입찰서류를 만든다 → 화면에서 고치고 한글로 내려받는다.
  • 기초자료는 과거 입찰 준비 파일(D드라이브 용역준비 폴더 등)에서 뽑아 넣었다. 기업정보, 수행실적 60건(금액 확인 39건), 인사기록 인원 보충정보, 객원 연구자 29명이다. 씨앗 파일은 ~/workspace/data/입찰기초자료/씨앗_20261005.json이다.
  • 인사기록 시스템은 읽기 전용으로, 이름·직위·소속·재직상태·역할·참여사업만 읽는다. 연락처·주민번호·급여는 읽지 않는다.
  • AI는 고성능컴퓨팅 우선 규칙(hpc_route)을 따른다. 사람 이름은 AI에 보내지 않고 「〔인력01〕」 같은 표식으로 보낸 뒤 결과에서 실명으로 되돌린다. 발주처 담당자 연락처는 지운 뒤 보낸다.
  • 영광읍 농촌중심지활성화사업 지역역량강화 용역으로 실제 시험했다. 분석 3분, 정량·입찰서류 각 1분 반, 정성 8분이 걸렸다. 결과 초안은 D드라이브 2026 사업/입찰제안서/영광읍_지역역량강화/에 있다.

작업 3 — 홈페이지 메뉴 개편 (sakyowon-site 레포)

  • 메뉴: 소개(지향·활동·걸어온 길·특장점) · 연구실(연구자료·정책지원관 지원시스템) · 쇼핑(교육프로그램·상품) · 그룹웨어(직원전용 질문·업무·근무·경영) · 문의.
  • 소개의 네 하위 메뉴와 경영공시는 첫 화면에 이어 붙여 스크롤로 보고, 하위 메뉴를 누르면 해당 절로 내려간다. 경영공시 카드는 정관·규약, 재무제표, 조합원 현황 세 개만 남겼다.
  • 옛 「서비스」 메뉴와 사이드바의 「직원전용 질문」 링크는 없앴다. 그룹웨어 하위 메뉴는 홈페이지 안에서 그룹웨어의 해당 탭을 연다. 그룹웨어 자체 사이드바 묶음도 같은 이름으로 맞췄다.
  • 커밋: ad73935(서비스→그룹웨어), 이후 메뉴 5개 개편, 교육프로그램 두 차례. 홈페이지는 push 후 동기화 스크립트로 즉시 반영했고 라이브에서 확인했다.

작업 4 — 교육프로그램 3종과 비용 계산·필요 진단

  • 주민자치 교육, 연대지능 활동가 교육, 문제해결 팀러닝. 모두 2시간 × 5강이고 강의를 골라 신청한다. 강의 제목은 이사장님 수정안 그대로다.
  • 비용 = 인원 × 시간 × 15,000원 + 출장비(전라권 20만원, 충청권·경상권 30만원, 수도권·강원권 35만원).
  • 강의마다 「우리에게 필요할까?」 질문 5개가 있고, 3개 이상 해당하면 「필요합니다」라고 알리고 그 강의를 신청 목록에 넣는다.
  • 「이 조건으로 문의하기」는 문의 양식에 강의·인원·지역·예상 비용·진단 결과를 채워 넣는다.

작업 5 — 중소기업확인서·신용등급 재확인

  • 옛 제안서 기준으로는 둘 다 만료로 보였으나, 법인 문서방 원본을 보니 중소기업확인서(소기업·소상공인)는 2027년 3월 31일까지, 신용평가등급(BB0)은 2027년 6월 30일까지 유효했다. 중소기업확인서는 스캔본이라 글자 인식 후 이미지를 직접 보고 대조했다.
  • 신용평가 확인서의 2025년 결산 값으로 자본금·종업원 수를 정정했고, 설립일은 이사장님 지시대로 2017년 설립과 2020년 사회적협동조합 인가를 함께 적는다.
  • 이를 반영해 영광읍 정량제안서를 다시 만들어 보냈다(재무구조 예상점수 2점 → 4~5점).

레슨

  • 고성능컴퓨팅 엔진의 답은 한 번에 약 3,500자에서 끊긴다. 긴 문서는 항목·절 단위로 나눠 써야 한다. 1만 8천 자쯤 입력하면 90초를 넘겨 실패하고 대체 경로로 넘어가는 일이 잦아서, 덩이와 절을 동시에 3개씩 돌리게 했다.
  • 엔진이 지시문을 그대로 베끼거나, 자격증이 없는데 가산점 10점을 매기는 답을 냈다. 답 모양을 검사해 버리고 다시 쓰게 했고, 가점은 기록된 자격만 인정하라고 지시했다. AI 초안의 점수는 반드시 사람이 확인해야 한다.
  • 문서의 확인 상태는 옛 제안서가 아니라 원본 증명서로 판단한다. 만료라고 보고했던 두 서류가 실제로는 재발급돼 있었다.
  • pkill -f는 자기 셸까지 죽인다(이번에도 한 번 당했다). 프로세스는 pgrep로 번호를 확인해 끝낸다.
  • 공공데이터포털은 법인 명의 가입이 휴대폰 본인인증과 맞지 않는다. 개인 명의로 가입해도 키는 똑같이 쓸 수 있다.

미완료

  1. (이사장님) 그룹웨어 「참여인력」에서 직원별 학력·자격증 채우기. 특히 한국농어촌공사 자격(농어촌개발컨설턴트 등)은 영광읍 같은 공고에서 최대 10점 가산이다.
  2. (이사장님) 인사기록에 없는 7명을 객원으로 임시 넣어 두었다. 재직 여부를 알려 주시면 정리한다.
  3. (데카) 10월 8일 첫 자동 발송이 제대로 됐는지 저널(journalctl --user -u g2b-bid-notice.service)과 발송 대장으로 확인하고, 걸리는 공고 수가 너무 많거나 적으면 키워드를 조정한다.
  4. (데카) 분석 결과의 제출서류 목록이 덩이마다 겹쳐 길다(영광읍 62건). 합칠 때 비슷한 이름을 더 잘 묶도록 고친다.
  5. (이사장님 결정) 경영공시를 메뉴에 따로 둘지, 출장비에 제주·온라인을 둘지.
  6. (데카) 홈페이지 새 메뉴 번역은 한국어·영어만 넣었다. 다른 6개 언어는 한국어로 보인다.
