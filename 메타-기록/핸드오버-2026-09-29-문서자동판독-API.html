핸드오버 2026 09 29 — 문서 자동판독 API 자력 구현, 지미 편지 정정, 감시 배선

세션 요약

전날 핸드오버(핸드오버-2026-09-28-햇소자-법령엔진-자료함) 이후 이어진 작업이다. 조합원 명부 파서로 클라이언트 파싱 4종을 마치고, 지미에게 요청해 두었던 문서 자동판독 API를 직접 구현했다 — 알고 보니 품앗이 자원이 필요 없는 사교원 API 서버 몫이었다. 그 과정에서 지미가 09:2x·10:1x·11:03 세 번에 걸쳐 남긴 정정·권한 인계를 반나절 못 읽고 있었다는 것이 드러나, 편지함 감시기를 만들고 잘못된 편지 세 통과 핸드오버 서술을 바로잡았다.

1. 조합원 명부 파서 — 클라이언트 파싱 4종 완료

deka2026.github.io PR #13 (13879f7). 개인정보라 원칙 셋을 코드에 박았다.

  1. 서버로 안 보낸다 — 파싱도 저장도 브라우저 안에서 끝난다
  2. 최소수집 — 성명·직위·가입일·출자금(+좌수)만 가져오고 나머지 열은 버린다. 무엇을 버렸는지 요약에 적는다
  3. 주민등록번호가 있으면 아예 들이지 않는다 — 파일 전체를 먼저 훑어 형태를 찾으면 파싱을 중단하고 열을 지우고 다시 올리도록 안내한다

재업로드는 성명(+가입일)으로 맞춰 갱신하는 멱등 병합으로 갔다. 다른 유형은 해시로 차단하지만 명부는 갱신 목적의 재업로드가 정상이기 때문이다.

이로써 bank·kepco(CSV)·rems·roster 네 가지가 서버 없이 브라우저에서 처리된다.

2. 문서 자동판독 API — 직접 구현

deka2026/sakyowon-server 85ae542, 화면 쪽은 deka2026.github.io PR #14 (8dd8a0e).

POST /api/docs/ingest (+ GET /api/docs/kinds)를 사교원 API 서버(:8787, /opt/sakyowon/server/)에 붙였다. 새 모듈 docs_ingest.py가 본문을 꺼내고 유형별 추출기가 값을 뽑는다.

항목내용
지원 형식PDF(pypdf) · HWPX(zip 안 XML이라 별도 라이브러리 불필요) · XLSX(openpyxl) · CSV/TXT
미지원구형 .hwp(olefile 없음) · DOCX(python-docx 없음) · 스캔 이미지(OCR 없음) — 전부 사람 말로 거절한다
유형 4종kepco(한전 정산명세) · permit(발전사업 허가증) · selection(선정 통보 공문) · land(토지대장)
응답{값, 확신, 위치}. 못 읽은 필드는 키를 뺀다 — 빈 문자열이면 “못 읽음”과 “0”을 구분할 수 없다

🔴 원본을 저장하지 않는다. 메모리에서 읽고 값만 돌려준 뒤 버린다(15MB 상한). 개인정보가 섞인 서류가 디스크에 남지 않게 하려는 설계다.

화면 쪽은 지금까지 /api/docs/ingest 에 메타(kind·name)만 보내고 있어 서버가 생겨도 읽을 파일이 없었다. FormData 로 파일을 함께 보내도록 고치고, 확신도를 제안 출처에 자동판독 · 확신 85% · 1쪽 으로 적게 했다.

이로써 한 바퀴가 닫혔다 — 자료를 올리면 → 값이 뽑히고 → 사람이 확정하면 → 기한 계산(선정일 +6개월, 허가일 +12개월)과 법령 판정(설비용량·소재지·지목)이 자동으로 돈다.

검증: 한글 문서 표본 4종 16필드 전건 일치, 실제 PDF(국토부 고시)로 PDF 경로 확인, 오탐 0(토지 정보 없는 문서에 land 를 돌려도 빈 결과), 여분 포트(8799) 선검증 후 교체, 라이브 아펙스 경유 종단 통과.

3. 지미 편지 3건을 반나절 못 읽었다

지미가 09:2x·10:1x·11:03 에 남긴 것을 15시에야 봤다. 내용은 셋 다 내 작업 전제를 뒤집는 것이었다.

  • 09:2x — ~/workspace/CLAUDE.md 대개편. 「데카는 서버를 못 만진다 → 이사장님이 붙여넣게 한다」를 걷어냈다. “이사장님을 네 손으로 쓰지 마라.” 사람 손이 필요한 칸은 승인·대외 발송·사람만 가능한 클릭·방향 넷뿐이다
  • 10:1x — 🔴 지미의 자기 정정. “아펙스 배포는 CF Pages 직접업로드라 내 몫”이라던 것이 틀렸다. sakyowon-www Pages 의 domains 에는 아펙스가 없고 cre.sakyowon.co.kr 하나뿐이다. 아펙스 배포는 처음부터 데카 몫이었다
  • 11:03 — 사교원 CF 토큰을 데카 방에 인계(~/.config/cf/sakyowon-www.env). 다만 cre 전용이고, 스코프가 DNS·터널·존까지 열려 있어 Pages 배포 외 용도로 쓰지 말 것

그래서 바로잡은 것 셋

  1. 편지 세 통의 전제가 틀렸다 — “CF 토큰이 없어 못 민다”고 두 번, “apex 업로드는 네 몫”이라고 한 번. 정정 편지를 올렸다(670410f)
  2. 전날 핸드오버 서술 수정 — “지미가 이관을 끝내 준 덕에”라고 적었으나 원래 데카 일이었다. 지우지 않고 틀렸던 기록과 정정을 같이 남겼다
  3. /api/docs/ingest 요청 취소 편지(909cd2f) — 내가 직접 만들었으니 중복 작업 하지 말라고 알렸다. 표 문서 라벨 간격·HWPX 문단 함정 둘도 엔진 쪽에 참고하라고 적어 보냈다

4. 배선 — 같은 일을 반복하지 않게

  • 🟢 jimmy-reply-watch.timer(10분) — JIMMY-DECA.md 에 새 「지미 → 데카」 글이 붙으면 이사장님 텔레그램 개인 방으로 알린다. ~/.local/bin/지미답장감시. 작업 트리를 건드리지 않고 git show origin/main: 으로 읽는다. 첫 실행은 기존 39건을 “본 것”으로 기록하고 조용히 물러난다
  • 🔴 www-src/deploy-www.sh 모순 해소 — CLAUDE.md 와 지미 편지가 둘 다 이 경로를 부르라고 적었는데, 정작 그 파일은 “폐기된 사본이다” 하고 exit 1 이었다. 문서가 시키는 명령이 거부되는 상태였다. 옛 로직은 실행하지 않고 정본으로 exec 하도록 고쳤다(백업 deploy-www.sh.bak_20260928_stub)

레슨

  1. 「내 권한 밖」이라고 단정하기 전에 한 번 해 봐라. ls ~/.config/cf 와 which wrangler 가 비었다는 것만 보고 “못 한다”로 결론지었는데, deploy-www.sh 는 이미 deka:deka 소유로 그 기계에 있었다. /api/docs/ingest 도 마찬가지로 남의 일인 줄 알았는데 내 서버 일이었다. 도구가 없는 것과 그 일을 할 수 없는 것은 다르다.
  2. 동료 편지함은 작업 시작 때 읽는다. 기억으로 때우려 하지 말고 배선으로 막아라(→ 감시 타이머).
  3. 표 문서는 라벨과 값 사이 공백이 길다. SMP 단가 142.5 를 [^\d]{0,12} 로는 못 잡는다. 넓히되 같은 줄 안으로 제한해야 한다([^\d\n]{0,25}) — 줄을 넘기면 라벨만 있는 줄이 다음 줄 숫자를 물어 엉뚱한 값이 들어간다. 이 오염 케이스를 일부러 만들어 시험했다.
  4. HWPX 문단을 공백으로 이으면 안 된다. <hp:p> 단위로 줄을 나눠야 한다. 안 그러면 「사업명」에 뒤 문장까지 딸려 들어간다.
  5. 내가 쓴 레슨을 한 시간 뒤에 다시 밟았다. 「bash 한글 변수명」 레슨을 쓰고 나서 deploy-www.sh 를 고치며 정본=... 을 써서 똑같이 당했다. 레슨은 적는 것으로 끝나지 않는다.
  6. 문서가 시키는 명령이 실제로 도는지 확인하라. 지시문과 실물이 어긋나 있으면, 다음 사람은 문서를 믿고 막힌다.

미완료

  1. 실제 서류로 추출 패턴 맞추기 — 표본이 필요하다. 지금 패턴은 합성 표본 기준이다. 진짜 한전 정산명세·발전사업 허가증 몇 장을 넣어 보면 실물에 맞출 수 있다. 이사장님께 표본을 받는 것이 다음 한 걸음이다.
  2. 자동판독 나머지 6종 — consent·minutes·quote·articles·registry·invoice. 같은 틀에 추출기만 더하면 된다. minutes·articles 는 DOCX·구형 HWP 가 흔해 python-docx·olefile 설치가 필요한데, sudo 가 되니 데카가 직접 하면 된다.
  3. 조합원 명부의 서버 보관 방침 — 사람이 정할 일. 지금은 브라우저 안에서만 처리하고 주민번호는 차단한다. 서버 보관 여부·기간·암호화가 정해지기 전에는 이 상태를 유지한다.
  4. cre CF 토큰 스코프 좁히기 — 지미 몫. DNS·터널·존까지 열려 있다. 급하지 않다.
  5. 분산에너지법 시행령 다목 — 입법 감시(2026-12-16 시행 전). 성장촉진지역이 아닌 마을(전남에서는 담양·영암·무안)은 이 시행령에 들어가야 우선접속을 받는다. 의견제출이 유일한 통로다.
  6. 영농형태양광법 시행령 — 입법 감시(2026-12-17 시행). 영농유지율·면적 상한·패널 높이가 미정이다. 고흥 해창만 1MW×100 분양형 모델의 부지 소요가 여기서 갈린다.
