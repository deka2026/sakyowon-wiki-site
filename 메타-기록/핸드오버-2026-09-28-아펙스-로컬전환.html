핸드오버 2026-09-28 — sakyowon.co.kr 아펙스를 CF Pages에서 완도 B로

세션 요약

이사장님이 “서버를 로컬로 변경했어, 확인하고 작업해”라고 하셔서 시작한 세션이다. 확인해 보니 의도는 있었으나 실제 배선은 안 돼 있었고, 아펙스는 여전히 CF Pages가 서빙하고 있었다. 그래서 가비아와 함께 사라진 deploy-www.sh 를 되살려 완도 B에 정적 번들을 세우고, 클라우드플레어 터널 ingress와 DNS를 바꿔 아펙스를 이 기계로 넘겼다. 전환은 11:00경 완료됐고, 라이브 13개 경로를 확인했다. 같은 세션 앞부분에서 완도 B에 텔레그램 올려 통로도 붙였다.

작업 1: 텔레그램 통로 개통 (완료)

봇 @deka2026_bot 과 일영민수 방은 2026-09-26에 노트북에서 이미 열려 있었는데, 완도 B에는 배선이 없었다. 노트북 기록에서 방 번호를 찾아 이어 붙였다.

첫 글 message_id 98. 4096자 분할, --미리보기(안 보내고 확인), --점검(열쇠 생존)을 갖췄다.

작업 2: 아펙스 정적 번들을 완도 B에 세움 (완료)

~/workspace/sakyowon-server/deploy-www.sh 에 가비아 원본이 남아 있어 그것을 되살렸다.

  • 웹루트: /opt/sakyowon/www (90MB, 8개 레포를 펼친 것)
  • 서버: /opt/sakyowon/www-src/server.py, Flask, 127.0.0.1:8041
  • 서비스: sakyowon-www.service (user 유닛, enabled)
  • 배치 스크립트 정본: sudo bash /opt/sakyowon/home/static/server/deploy-www.sh

서버에 CF Pages 동작 두 가지를 흉내냈다. 이게 없으면 quartz 위키 링크가 전부 404 난다.

  1. 확장자 없는 주소 → 같은 이름의 .html (/foo → /foo.html)
  2. 폴더 주소 → 그 안의 index.html

웹루트 밖으로 나가는 경로(../)는 막았다.

작업 3: 터널 ingress·DNS 전환 (완료)

/opt/sakyowon/www-src/apex-cutover.py 를 만들어 수행했다. 기본이 「보기」 모드라 그냥 실행하면 계획만 보여주고 아무것도 바꾸지 않는다. --실행 으로 적용하고 --되돌림 으로 복구한다.

ingress — 기존 6개는 그대로 두고 두 줄을 추가했다.

호스트원점
sakyowon.co.kr · www.sakyowon.co.krhttp://127.0.0.1:8041 (새로)
api svc vitality bid deka home그대로

DNS — 주소 레코드 2개만 CNAME → <터널ID>.cfargotunnel.com (proxied)로 교체했다.

CF API 토큰 — 이사장님이 발급하셔서 주셨다. ~/.cf/.토큰 권한 600. 권한은 Account:Cloudflare Tunnel:Edit · Zone:Zone:Read · Zone:DNS:Edit · Account:Cloudflare Pages:Edit 네 줄이고 범위는 sakyowon.co.kr 한 영역이다.

작업 4: Pages 커스텀 도메인 분리 (이사장님 수행)

ingress와 DNS를 다 바꿨는데도 아펙스가 계속 CF Pages로 갔다. Pages 프로젝트 sakyowon-www 에 sakyowon.co.kr 이 커스텀 도메인으로 붙어 있었고, 클라우드플레어는 이 바인딩을 DNS 레코드보다 우선하기 때문이다. 이사장님이 대시보드에서 두 도메인을 떼신 뒤 즉시 넘어왔다.

Pages 프로젝트 자체는 살려 뒀다. 지금 이 Pages가 가진 주소는 cre.sakyowon.co.kr 하나뿐이다.

DNS만 보고 판단하지 않고, 로컬 웹루트에만 있는 표식 파일을 만들어 라이브에서 그것이 나오는지로 검증했다.

레슨

  1. 🔴 DNS 레코드를 지울 때 주소 레코드(A·AAAA·CNAME)만 건드려라. 첫 판 스크립트는 아펙스의 레코드를 전부 지우게 돼 있었고, 거기에 하이웍스 메일 MX 두 개와 SPF TXT 가 들어 있었다. 그대로 돌렸으면 사교원 메일이 죽었다. 「보기」 모드로 먼저 출력해 본 덕에 잡았다. 인프라를 바꾸는 스크립트는 기본이 「보기」여야 한다.

  2. 🔴 Pages 커스텀 도메인이 DNS보다 세다. ingress와 DNS를 아무리 정확히 바꿔도 Pages 프로젝트가 그 호스트를 쥐고 있으면 트래픽은 Pages로 간다. 「어느 Pages 가 그 주소를 갖고 있나」를 먼저 확인해야 한다. 이걸 몰라서 한 바퀴 헛돌았다.

  3. 🔴 반영 확인은 DNS·헤더가 아니라 표식 파일로 한다. 클라우드플레어를 끼고 있으면 응답 헤더가 Pages와 자체 서버가 비슷해 구별이 안 된다. 로컬에만 있는 파일을 만들어 라이브에서 불러보는 것이 유일하게 확실하다.

  4. bash 변수 이름에 한글을 쓸 수 없다. 답=... 같은 줄은 command not found 로 죽는다. 게다가 bash -n 은 이걸 못 잡는다(런타임에 명령어로 해석되기 때문). 한글 이름을 쓰고 싶으면 파이썬으로 짜라. 이번 세션에서 같은 함정에 세 번 걸렸다.

  5. 「없다」고 말하기 전에 다른 기계 기록부터 뒤져라. 텔레그램 봇이 없다고 판단했는데 9월 26일 노트북에서 이미 열려 있었다. knowledge/memory/laptop-admin/ 에 방 번호까지 적혀 있었다. 이 기계에 없는 것과 존재하지 않는 것은 다르다.

  6. 여러 데카가 동시에 같은 문서를 고친다. 이 세션 도중 다른 세션이 09:58과 11:02에 스킬 파일들을 고쳤다. 고치기 전에 수정 시각과 현재 내용을 반드시 다시 읽어라. 덮어쓰지 말고 아직 낡은 곳만 짚어라.

  7. /opt/sakyowon/www-src/deploy-www.sh 는 쓰지 마라. 08:23에 급히 만든 갈라진 사본이고, 레포판에 있는 소유자 보정 블록이 빠져 있다. 지금은 안내문만 찍고 종료하도록 바꿔 뒀다. 정본은 sudo bash /opt/sakyowon/home/static/server/deploy-www.sh 다.

미완료

  1. 허브에서 비활성 처리된 카드 3개 — 고향사랑기부제 정보센터, 입찰메이트, 서남해 그랜드. 사이트가 죽은 게 아니라 허브 index.html 에서 의도적으로 링크를 막아 둔 것이다(data-href + is-disabled). /hometown-love/ 는 200으로 정상 서빙된다. 켤지 말지는 이사장님 판단.
  2. 텔레그램 message_id 98 을 지미에게 전달 — 봇끼리 글을 못 보는 구조라 자동으로 안 잡힌다. 다만 그 글의 내용(위키 반영 요청)은 아펙스 전환으로 필요 없어졌다. 통로 개통 보고만 남는다.
  3. CF 토큰 관리 — ~/.cf/.토큰 이 이 기계에만 있다. 기계가 바뀌면 다시 발급해야 한다. 만료일은 걸지 않았다.
